01Năm data objects

Đừng dùng một từ “dataset” cho năm vật thể có lifecycle và failure mode khác nhau.

Task

Task specification

User goal, initial state, allowed tools, constraints, output contract và success criteria. Đây là thứ được split và đo coverage.

World

Environment snapshot

Container/image, fixture, repository commit, tool schema, seed, clock và network policy. Không version nó thì một task ID có thể đổi nghĩa.

Behavior

Trajectory

Raw token buffer, messages, actions, observations, tool errors, latency, termination và policy version. Đây là dữ liệu thật sự đi vào loss.

Signal

Supervision record

Outcome, reward components, rubric decisions, teacher scores, masks và verifier version. Tổng reward không đủ để debug.

Truth

Evaluation case

Task held-out, environment cố định và strict scorer độc lập. Không được tự động biến đổi theo training reward.

Rule

Version như một bundle

Một release data phải pin cả năm object. “Prompt v3” chạy với “fixture latest” không phải một experiment reproducible.

02Lifecycle: từ workflow tới training token

1 · ContractĐịnh nghĩa task, output, tools và evaluator trước khi sinh data.
2 · GenerateMine workflow thật, procedural generation và controlled perturbation.
3 · ValidateSchema, executable, deterministic, solvable, safe và non-leaking.
4 · BaselineChạy base + frontier model; đo pass@k, variance và failure taxonomy.
5 · SplitKhóa family-aware train/val/test/challenge split trước khi tune.
6 · CollectExpert traces, student rollouts, recovery paths và tool outcomes.
7 · ScoreOutcome, rubric, teacher signal và strict independent evaluation.
8 · RefreshRe-score difficulty, update mixture và retire stale/broken tasks.
Thứ tự quan trọng. AWS đặt environment và external evaluation trước reward/training. Làm ngược lại khiến mỗi data iteration thay cả “thước đo”, không còn biết gain đến từ data hay evaluator loophole.

03Canonical trajectory schema

Schema dưới đây là synthesis thực hành, không phải format bắt buộc của một framework. Điểm quan trọng là giữ lineage và raw tokens ở boundary có thể audit.

task: { id, family_id, template_id, source, license, split goal, constraints, output_contract, difficulty_snapshot } environment: { image_digest, fixture_version, repo_commit, seed, tool_schema_hash, clock, network_policy } policy: { model_id, checkpoint, tokenizer_hash, chat_template_hash, harness_version, sampling_config, behavior_policy_step } trajectory: { raw_token_ids, assistant_token_mask, turns[], actions[], observations[], tool_errors[], termination_reason, latency } supervision: { outcome, reward_components, rubric_results, verifier_version, teacher_id, teacher_logprobs, valid_mask } lineage: { generator, parent_ids, created_at, content_hash, pii_status, secret_scan, review_status }
  • Lưu raw token IDs. TITO cho thấy decode → render → retokenize có thể đổi token boundary và làm assistant mask sai.
  • Pin environment bằng digest/commit. Tag như latest làm cùng task tạo outcome khác nhau theo thời gian.
  • Ghi behavior-policy version. Async rollout không có trường này thì không thể đo staleness hay lọc trajectory quá cũ.
  • Giữ reward components riêng. Một scalar tổng che việc model đang game format term hoặc một rubric con.

04Task taxonomy và coverage

“Có 100K task” không nói được corpus có cover deployment hay không. Coverage phải được đo theo hành vi và environment, không chỉ topic.

DimensionVí dụ bucketRủi ro nếu thiếu
DomainCode · research · office · support · cyberModel chỉ transfer trong một workflow hẹp
Tool topologySingle tool · chain · parallel · nested/sub-agentBiết call tool nhưng không biết orchestration
Horizon1–3 · 4–10 · 11–30 · 30+ decisionsShort-task gain không chuyển sang long-horizon
StateStateless · persistent · partially observableKhông học state tracking hoặc recovery
Failure modeWrong tool · wrong args · tool error · loop · bad stopHappy-path corpus không dạy recovery
DifficultyPolicy-relative pass@k bandsBatch toàn all-pass/all-fail, không có advantage
Output contractFree text · JSON · patch · database stateReward parser và deploy contract lệch nhau
Safety boundaryRead-only · write · destructive · networkedAgent học hành động không được phép deploy
Coverage ≠ balance. Một bucket có mặt chưa có nghĩa nó nhận đủ gradient. Luôn báo cáo ít nhất: sequence share, response-token share, accepted-group share và rollout-compute share.

05Data contract theo training stage

SFT

Expert traces

Dùng khi base model chưa biết protocol hoặc không có foothold.

  • Correct end-to-end traces
  • Tool call + observation đầy đủ
  • Nhiều strategy/checkpoint
  • Recovery traces, không chỉ happy path
OPD / MOPD

Prompts + teachers

Dùng khi student đã sinh được action trong support của teacher.

  • Teacher routing/domain label
  • Student raw rollout
  • Teacher token scores
  • Prefix/refinement data khi support lệch
RL

Tasks + world + verifier

Dùng khi outcome có thể thực thi và exploration tạo thêm giá trị.

  • Resettable environment
  • Outcome-first verifier
  • Reward variance
  • Held-out strict evaluator
Nếu thấyCan thiệp data trướcKhông nên làm ngay
Base reward luôn 0Task dễ hơn, SFT seed traces, curriculumTăng batch hoặc đổi PPO/GRPO
Biết protocol nhưng solve yếuThêm executable RL tasks và verified partial progressNhồi thêm format demonstrations
Teacher giỏi, student gần teacherOn-policy distillation trên student tokensTeacher-generate toàn bộ long traces mặc định
Student rollout drift quá sớmLight SFT, teacher prefix hoặc refined trajectoriesTin dense KL trên off-manifold prefix
Domain này học, domain kia regressToken-share balance, specialist teacher, staged curriculumChỉ cân bằng số prompt

06Task và trajectory generation

  1. Mine workflow thật, nhưng tách dữ liệu nhạy cảm. Lấy task structure, tool graph và failure pattern; thay customer state bằng fixture hoặc synthetic entity.
  2. Generate từ specification, không chỉ paraphrase prompt. Thay initial state, hidden dependency, tool availability và success condition để tạo hành vi mới.
  3. Procedural generation phải giữ proof of solvability. Lưu generator seed và gold execution/checker; task sinh được nhưng không solve được là data poison.
  4. Perturb happy path có chủ đích. Inject wrong arguments, transient tool errors, stale observations, missing fields và ambiguous stop conditions để thu recovery traces.
  5. Giữ trajectory diversity. Sample nhiều expert/model/checkpoint, temperature và plan; deduplicate theo cả prompt lẫn action graph.
  6. Không biến critique thành answer leakage. Privileged state dùng cho teacher/verifier phải bị mask hoàn toàn khỏi student context.
  7. Replay trước khi publish. Mỗi trajectory/tool outcome phải chạy lại trên pinned environment; text nhìn hợp lý không đủ.
Bài học từ Scale. Dataset MCP hữu dụng vì task giữ full workflow complexity, error recovery, granular rubrics và tool diversity. Nhưng một corpus production còn phải bổ sung lineage, split discipline, leakage audit và environment pinning.

07Chín quality gates

01 · Schema

Đủ field, đúng type, token/action masks nhất quán.

02 · Executable

Environment khởi tạo và tool call chạy thành công.

03 · Deterministic

Replay nhiều lần cho outcome/scorer ổn định trong tolerance.

04 · Solvable

Gold/reference agent hoàn thành; không có field bất khả trả lời.

05 · Foothold

Base hoặc warm-start policy tạo reward variance khác 0.

06 · Verifier

Reward và strict evaluator đồng ý trên adversarial examples.

07 · Leakage

Không gold answer, hidden tests, repo history hoặc future data leak.

08 · Isolation

Mỗi rollout có state riêng; reset sạch; side effect bị chặn.

09 · Budget

Turn/token/tool limits đủ cho task nhưng không cho loop vô hạn.

Gate phải trả về reason code, không chỉ boolean. Một dashboard “92% valid” vô dụng nếu không biết 8% còn lại là flaky verifier, unsolvable task hay tool timeout.

08Split, contamination và held-out truth

Random row split thường rò template, repository, fixture hoặc generator seed. Agent nhìn thấy cùng một world dưới câu chữ khác và trông như đã generalize.

Train

Học và refresh

Cho phép re-score difficulty, thay mixture và retire task lỗi. Không bao giờ dùng để báo cáo cuối.

Validation

Tune có kiểm soát

Family-disjoint khi có thể; dùng để chọn checkpoint, curriculum và reward. Không sửa task sau khi thấy model output mà không bump version.

Held-out test

Khóa trước training

Strict scorer độc lập; tách theo template, repo, tool family, seed và temporal cutoff — không chỉ prompt hash.

Challenge

Failure-focused

Adversarial tools, long horizon, recovery, distribution shift và anti-hacking cases. Không trộn vào checkpoint selection.

  • Dùng seed khác nhau cho SFT demonstrations và RL tasks; Practitioner’s Guide làm vậy để tránh leakage.
  • Với code/SWE, split theo repository hoặc issue family; cùng repo khác issue vẫn có thể rò structure.
  • Với tool use, split theo tool composition/action graph, không chỉ tên server.
  • Deduplicate ở ba tầng: text similarity, structured task state và normalized action graph.
  • Giữ một scorer nghiêm hơn training reward; held-out bằng chính reward chỉ đo generalization, không bắt parser bug.

09Curriculum và dynamic sampling

Difficulty là thuộc tính của cặp task × policy checkpoint, không phải nhãn bất biến của task.

Bucket theo rolloutÝ nghĩaXử lý
All-passGroup advantage gần 0; task đã bão hòaGiảm sampling, giữ một phần làm regression canary
Mixed-passCó variance; vùng học hiệu quả nhấtƯu tiên nhưng theo dõi diversity và reward hacking
Mostly-failFrontier task; có thể tạo exploration valueGiữ quota nhỏ, thêm partial verifier hoặc curriculum
All-failKhông có learning signal hoặc task lỗiPhân biệt unsolved với unsolvable; SFT/prefix/repair trước

Bốn mixture phải xem cùng lúc

Sequence shareTỷ lệ prompt/trajectory theo domain hoặc task family.
Token shareGradient budget thật; Open-MOPD cho thấy prompt-balanced vẫn có thể token-skewed.
Accepted shareSau filter all-pass/all-fail, source nào thực sự vào batch.
Compute shareRollout time, verifier latency và environment cost theo source.
  1. Re-score theo checkpoint. Chạy periodic probe rollouts để cập nhật pass-rate bucket.
  2. Curriculum từ simple tới compositional. Practitioner’s Guide cho thấy skill state-tracking từ environment đơn giản có thể transfer lên task phức tạp.
  3. Không giả định cross-domain SFT luôn tốt. Paper cũng quan sát prior từ domain khác có thể làm multi-turn RL tệ hơn.
  4. Bound stale trajectories. Log behavior-policy step, sample age và importance ratio; drop/re-score khi vượt policy.
  5. Giữ hard set làm frontier eval. Không xoá toàn bộ all-fail; tách khỏi main training mixture để đo capability frontier.

10Rubric và reward cũng là data

Reward definition, rubric text, judge prompt và parser đều phải version, review và test như source code.

Outcome first

Ưu tiên state có thể kiểm chứng

Unit tests, database state, exact artifact hoặc environment transition mạnh hơn nhận xét “có vẻ đúng”.

Dense carefully

Partial credit phải có nghĩa

Chỉ thêm component nếu nó thật sự tiến gần task success. Log từng component để thấy term nào bị game.

Rubric data

Essential và observable

Mỗi criterion phải map tới evidence trong trajectory/world, có positive/negative example và rule cho missing evidence.

Independent truth

Reward không tự kiểm tra mình

Chạy strict evaluator trên cùng rollout; audit các case reward cao nhưng outcome fail và ngược lại.

  1. Unit-test parser bằng adversarial outputs. Missing wrapper, duplicate field, invalid JSON, partial patch và tool exception.
  2. Calibrate judge. Blind human sample, pairwise agreement, repeatability và sensitivity theo prompt order/verbosity.
  3. Không chấm hidden reasoning style. Reward observable behavior/outcome; tránh ép một chain-of-thought form duy nhất.
  4. Version rubric cùng task. Thay rubric làm data distribution đổi; không overwrite kết quả cũ.
  5. Giữ disagreement queue. Reward–eval disagreement là nguồn data curation giá trị nhất, không chỉ là metric xấu.

11Governance, safety và provenance

License

Ghi nguồn và quyền dùng cho prompt, repo, trace, model-generated data.

PII

Detect/redact trước generation; không kỳ vọng model “quên” sau training.

Secrets

Scan tokens, credentials, hidden tests, local git history và environment variables.

Isolation

Network off-by-default, allowlist proxy, per-episode sandbox, teardown chắc chắn.

Lineage

Parent task, generator, reviewer, code commit, model checkpoint và timestamps.

Deletion

Có index để tìm mọi derivative trajectory khi source cần gỡ bỏ.

Agentic-specific threat. Golden answer có thể rò qua Internet, package cache, git history, test files hoặc tool description. Leakage scan chỉ trên prompt text là chưa đủ.

13Checklist trước hero run

  1. Data contract được ký chung. Research, data và platform đồng ý task, environment, schema, reward và eval ownership.
  2. Held-out split đã khóa. Family/repo/tool/seed/temporal overlap được audit, không chỉ exact duplicate.
  3. 100% task qua schema + executable gate. Determinism và solvability có threshold công bố.
  4. Base và frontier baselines đã chạy. Biết foothold, ceiling, pass@k buckets và failure taxonomy.
  5. Reward parser đã test trên raw outputs. Có strict evaluator độc lập và disagreement queue.
  6. Mixture được báo cáo theo bốn trục. Sequence, token, accepted groups và compute.
  7. Overfit pilot thành công. 16–32 task mixed-pass có thể học; failure không đến từ harness/tool.
  8. Lineage đủ để replay. Pin policy, tokenizer, chat template, harness, environment, verifier và seed.
  9. Safety review hoàn tất. License, PII, secret, network, destructive action và deletion workflow.

Final rule

Nếu không thể replay một task, giải thích vì sao nó nằm trong batch, biết policy nào sinh trajectory và chứng minh strict evaluator chấm đúng deploy outcome, thì đó chưa phải training data — mới chỉ là một mẫu log khó kiểm soát.
