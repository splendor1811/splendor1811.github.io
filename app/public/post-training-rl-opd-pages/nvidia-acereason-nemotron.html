AceReason-Nemotron

Một reference gọn và tái sử dụng được cho việc train reasoning model 7B/14B: strict on-policy GRPO, curriculum math → code → math, tăng context theo stage và verifier hoàn toàn rule-based.

01 · Vì sao paper này quan trọng?

AceReason không phải agentic multi-turn model. Giá trị của nó là một thí nghiệm sạch về ordering và retention: math RL cải thiện cả coding, rồi code RL tiếp tục tăng code mà gần như không xoá math.

Vai trò trong report tổng. Đây là tiền lệ trực tiếp cho tư duy Cascade: tách domain có verifier/latency khác nhau, sắp xếp stage theo transfer thực nghiệm, và dùng strict on-policy training để giữ entropy.

02 · Method cốt lõi

Start từ reasoning SFT.
DeepSeek-R1-Distill-Qwen 7B và 14B là baseline, giúp giữ distillation data/fine-tuning compute cố định.
Group rollout.
Mỗi prompt sinh 8 hoặc 16 response; binary reward được chuẩn hoá trong group và broadcast xuống token.
Một update duy nhất.
Rollout policy là policy được update; importance ratio = 1, KL coefficient = 0. Objective thực tế là REINFORCE với group-normalized reward.
Curriculum theo length/difficulty.
Math tăng 8K → 16K → 24K → 32K; prompt đã quá dễ bị bỏ. Code có hai stage và tăng sampling temperature để mở exploration.

Team báo cáo khi dùng 2–4 gradient update cho cùng rollout batch, entropy collapse xuất hiện khoảng 100 step. Một update/rollout batch ổn định hơn. Đây là trade-off rõ: sample efficiency theo batch thấp hơn, nhưng data luôn thật sự on-policy.

03 · Math → Code → Math

StageLength / samplingMục tiêu
Math RL 18K → 16K → 24K; hard-prompt curriculumHọc reasoning ổn định với compute thấp trước, rồi mở budget
Code RL 124K, temp 0,6, 8 rollout; difficulty cap theo model sizeKhởi động convergence bằng task vừa sức
Code RL 232K, temp tăng 0,6 → 1,0; rollout 8 → 16Dần tăng exploration, filter prompt dễ mỗi epoch
Math RL 232KPhục hồi/củng cố math sau code specialization

Bắt đầu trực tiếp ở 24K tốn GPU hơn nhưng gain kém. 8K stage ban đầu làm accuracy giảm do policy phải nén reasoning; sang 16K, response length tăng nhanh và accuracy bật lên. Vì vậy “short first” là curriculum optimization, không phải tuyên bố rằng reasoning ngắn luôn tốt hơn.

Cross-domain transfer

Math-only RL tăng LiveCodeBench trên cả topic không thuần toán. Sau code RL, code score tăng tiếp, còn AIME thay đổi nhỏ. Kết quả này hỗ trợ giả thuyết RL trên reasoning verifier sạch có thể học procedure chung; nhưng không chứng minh mọi pair domain đều tương hỗ.

04 · Data và reward đáng tin trước

Math verifierSymPy + ANTLR kiểm equivalence của answer trong \boxed{}. Chỉ correctness 0/1; không format reward, không length penalty.
Code verifierExtract Python code rồi chạy full test trong local sandbox. Chỉ pass toàn bộ test và trong time limit mới nhận 1.
Math curation49K problem sau decontamination, format filtering và DeepSeek-R1 majority verification; bỏ question quá dễ/ngắn hoặc mơ hồ.
Code curation8.520 problem sau bỏ interactive/special judge, siết edge-case test, deduplicate và loại difficulty 8/8-fail.

Verification cost chênh rất lớn: paper báo khoảng 3,9 giây/1.024 math instance nhưng 552,4 giây/1.024 code instance trên pool 64 worker. Đây là lý do hệ thống để tách math-only và code-only stage, ngoài lý do optimization.

False reward phá curriculum. False positive cho code sai một tín hiệu thắng; false negative phạt solution hợp lệ khác reference. Cả hai làm pass-rate difficulty sai, khiến sampler chọn prompt sai và policy-gradient học shortcut.

05 · Practice: baseline trước khi lên agent

  1. Xây verifier regression suite. Có correct alternative, edge case, timeout, memory limit và malformed output. Đo false-positive/negative trước khi train.
  2. Đừng reuse rollout quá nhiều. Nếu entropy/ratio bắt đầu collapse, giảm update-per-rollout về 1 trước khi thêm clip trick phức tạp.
  3. Mở context theo stage. Khởi đầu ngắn để throughput cao, chỉ tăng khi score/response length plateau. So sánh theo GPU-hour, không chỉ step.
  4. Difficulty là thuộc tính của policy. Re-evaluate pass@N theo checkpoint; filter prompt đã all-pass và prompt all-fail không tạo gradient.
  5. Sắp order bằng transfer matrix. Đo math→code và code→math riêng. Nếu stage sau phá domain trước, thêm replay mixture hoặc consolidation checkpoint.
  6. Tách queue theo verifier cost. Code execution chậm hơn math hàng trăm lần; trộn naïve tạo straggler. Scheduler hoặc stage separation phải phản ánh wall-clock.

06 · Evidence boundary

  • Experiment dùng 128 H100, veRL và vLLM 0.7.3; throughput/hyperparameter không chuyển nguyên xi sang stack khác.
  • Reward binary sạch phù hợp math/code có oracle. Kết quả không trực tiếp giải quyết multi-turn credit assignment hoặc open-ended agent quality.
  • Cross-domain transfer được đo trên AIME/LiveCodeBench của 7B/14B; cần kiểm lại ở model/data/benchmark khác.
  • Model weights mở, nhưng custom verifier modification và exact curated training data không được đóng gói thành một reproduction hoàn chỉnh trong paper.
