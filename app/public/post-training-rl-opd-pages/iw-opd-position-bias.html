IW-OPD

Dense supervision bị position bias: khi prefix student drift khỏi teacher, token muộn vẫn có loss nhưng ít hữu ích. IW-OPD downweight chúng bằng prefix-importance.

Hiện tượng position bias

Trong controlled experiment, chỉ dùng 30% token đầu match hoặc vượt full OPD, còn 30% token cuối học kém. Không phải “token sớm luôn tốt”; prefix sớm thường còn nằm trong vùng mà teacher có xác suất tìm lại lời giải. Token muộn bị condition trên toàn bộ lựa chọn trước đó, nên teacher local distribution có thể không còn là correction target tốt.

Từ constrained optimization tới weight

Standard OPD dùng token advantage từ log-ratio teacher–student. IW-OPD nhân thêm tỷ lệ xác suất teacher/student tích lũy trên prefix, lũy thừa α. Prefix tương thích teacher giữ weight; drift tích lũy làm weight giảm.

Aₜ(IW-OPD) = (πT(y<t|x) / πθ(y<t|x))^α · Aₜ(OPD)
  1. Student sample response on-policy.
  2. Teacher score cùng response và tính cumulative prefix log-ratio.
  3. Chuyển log-ratio thành importance weight, dùng stop-gradient và clip để tránh explosion.
  4. Nhân weight trực tiếp vào PPO/OPD advantage rồi update.

Cách chạy và theo dõi

  • Official repo dùng 4 nodes × 8 GPUs cho Qwen3-4B/30B; bắt đầu scale nhỏ để tune α và weight cap.
  • Trong TRL, API nằm ở experimental.iw_opd; pin version vì docs cảnh báo API có thể đổi.
  • Log weight distribution theo position. Nếu gần như mọi suffix bằng 0, model không nhận supervision đủ dài; nếu heavy-tail, gradient dễ nổ.
  • Giữ vanilla OPD run cùng student/teacher/data làm đối chứng bằng cách tắt IW weight.
  • Repo dùng DeepMath-103K, AIME 2024/2025; code eval riêng theo EvalPlus.

Giới hạn

Importance weighting giảm ảnh hưởng prefix xấu nhưng không tạo recovery trajectory mới. Nếu teacher không thể cứu state, downweight là hợp lý nhưng cũng bỏ supervision. Kết quả chủ yếu trên math/code và một cặp Qwen; cần kiểm tra lại với tool-use, nơi observation từ environment làm prefix distribution khác text-only.
