Token-In, Token-Out

Trong multi-turn RL, gradient phải đặt lên đúng token policy đã sample. Decode → parse → render → re-encode có thể đổi token IDs mà text trông vẫn giống nhau; khi đó toán học on-policy đã bị phá.

Lỗi tưởng nhỏ nhưng phá objective

Agent sinh tool call tokens; harness decode để parse, chạy tool, append observation rồi render lại toàn conversation. BPE không invertible: nhiều token sequence decode thành cùng text, JSON whitespace/order và special tokens còn tăng số biến thể. Sequence trainer thấy sau re-encode có thể khác sequence inference engine thật sự sample.

Triệu chứng: loss spike, shape mismatch, logprobs lệch hoặc training “chạy được” nhưng gradient nằm trên token policy chưa từng sinh.

TITO construction

  1. Tokenize initial messages đúng một lần.
  2. Inference engine trả generated token IDs; lưu nguyên IDs và assistant mask.
  3. Decode chỉ để parse tool call. Không dùng parsed assistant message để dựng lại phần token đã sinh.
  4. Render tool message sao cho tokenized history cũ là prefix bất biến; append chỉ token mới của environment.
  5. Tiếp tục generate từ token buffer; cuối rollout backprop chỉ assistant-generated spans, mask user/tool/system spans.

Hai property tests bắt buộc

  • Round preservation: generated assistant token IDs trong stored trajectory phải byte-for-byte bằng output inference engine.
  • Prefix preservation: khi append tool result, toàn bộ token sequence cũ phải là prefix chính xác của sequence mới.
  • Fuzz JSON spacing, Unicode, empty content, multiple calls, booleans/null, tool error và truncated output.
  • Chạy test cho từng model/chat template; template update là breaking change đối với RL harness.
  • Log sample IDs và first divergence position để debug, không chỉ decoded strings.

Renderer hay TITO?

Hand-coded renderer có thể bảo đảm bridge đúng cho từng model family; Prime Intellect renderers cung cấp lựa chọn này. TITO generic giảm maintenance nếu chat template thỏa prefix-preserving property. Dù chọn cách nào, invariant quan trọng hơn library: policy loss phải dùng exact sampled IDs.

Bài tập trung correctness của trajectory representation, không đánh giá thuật toán PPO/GRPO nào tốt hơn.

Preflight gate

Không bắt đầu multi-turn RL run trước khi property tests pass trên mọi template/model được train.
